# v0.19.0 release retro (2026-11-19)

## What went well

- **The warden loop held up under load.** Roughly 20 missions in two days (provider, cortex, ui-core, runtime, core, docs, tooling, release). Each brief named paths and gates, the parent re-ran the gates and committed per concern, and no warden commit or out-of-scope edit had to be reverted.
- **Instrument-first paid off twice.** The tooling-warden disproved my "warm bun cache hid the drift" theory with four cache variants before changing `repo ci`. The core-warden reproduced the src+dist double-load before rewriting the slot test. Both stopped a wrong fix.
- **Honest unknowns reached the user.** Costs absent instead of $0, `costComplete`, "live list unavailable: out of credits", "free" only where the price book says $0. The xAI out-of-credits case was found from a user screenshot and fixed at the framework boundary, with Cortex only rendering it.

## Open after release

- xAI account is out of credits: `grok-4.7` is not live-verified, and its 256K window is copied from grok-4.
- LiteLLM `/model/info` and the cost header are not verified against a live proxy.
- `runStream()` results have no `totalCost()`; stream users read `RunCostFinalized`.
- Post-release ablation of `budgetAnswerTurn` and `parallelToolHint` (both default-on).
- Resolved 2026-11-20, abort-signal flake: the test was at fault, not cancellation. Abort-to-end is 1 to 53 ms. The 559 ms came from the 50 ms abort timer firing late, because cold-start work blocked the event loop (about 75 ms idle, about 420 ms on a busy core). The test now measures abort-to-end against a 5 s scripted call; it fails when both interrupt paths are cut.
- New finding from that work, not yet investigated: the first run in a process blocks the event loop for about 75 to 420 ms, delaying any caller timers and abort handlers set during it.
- Resolved 2026-11-20, calibration flake: the pin asserts the newest arm write, which is the reader's contract.
- `trace-wire-facts` is not flaky: the file runs in 554 ms. Its 5 s timeout came from swap starvation (the suite took 34,436 s against a normal 465 s). Still open: the mirror could check free swap up front and refuse to start.

Our `^1.9.0` floated to 1.10.0, which every OTel SDK 2.x package peers `<1.10.0`. The range is now `~1.9.0`. `test:install` uses npm, which stays silent, so release checks missed it. Proposal: a Bun clean install that fails on peer warnings.
