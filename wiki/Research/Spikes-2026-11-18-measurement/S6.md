# S6: feasibility of the deterministic mock-provider tier and prefix-fork replay

Plan: [[2026-11-18-measurement-overhaul]] (Phase Z). Zero tokens, no live model.

## Pre-registered prediction (written before building)

1. Q1: `ReactiveAgents.create().withReplayLLM(layer)` accepts any `Layer<LLMService>` as the base LLM (replay keystone), so a policy layer works through the builder. `withTestScenario` does not (static turns only). `executeReactive` direct (seam tests) also works and is the faster path for harness-config arms.
2. Q2: a policy layer that routes by `request.purpose` and records requests can run one shape off vs on and give a deterministic verdict. Token counts from recorded requests will exceed `fakeUsage` and show the tool-schema saving of the lean turn that `fakeUsage` cannot.
3. Q3: the classifier peek protects only `toolCall` turns, so a text-first static script is eaten by a harness call (a `text` turn answers a classify call and advances the cursor). A purpose-routed layer is immune.
4. Q4: prefix-fork is feasible with the sequence-ordered replay table (Nth call gets Nth recorded response): replay first k responses, then hand the cursor to a policy. Missing: tool-surface erasure in recorded tool mode, `completeStructured` dies, no harness-config injection in `makeReplayAgent`.
5. Q5: same seed twice gives identical request logs (no wall-clock or Math.random in the path I control).

## Kill criteria

- KILL if a purpose-routed layer cannot keep harness calls from consuming the agent script, or the run through `executeReactive`/builder is non-deterministic under a fixed seed, or the on/off arm difference cannot be read from recorded requests.
- REDESIGN if it works but needs edits in `llm-provider`/`testing`/`runtime` for every shape (list them).
- PASS if all of Q1-Q5 hold with only small, listed fixes.

## Results

Code: `packages/benchmarks/src/sim/{policy-model,prefix-fork}.ts`; shape runner `packages/benchmarks/tests/sim-spike-shape.ts` (must live under tests: `check-cross-cutting` forbids `provideTestEnvelope` in production src, so a real `run-shape.ts` needs a sanctioned test-seam path or a gate allowance, owner decision); test `packages/benchmarks/tests/sim-spike.test.ts` (7 pass, typecheck clean). Zero tokens.

**Q1 (confirmed, prediction held).** Builder path: `.withReplayLLM(layer)` takes any `Layer<LLMService>` as the base LLM (`runtime.ts:429` `llmOverrideLayer`); `.withLayers` cannot (merges too late); `.withTestScenario` is static turns only. Direct path: `executeReactive` + `buildRunEnvelope({ harness })` + `mockToolServiceLayer` (the seam-test route) takes a harness config per arm with no env flag. Use the direct path for arms, the builder path for end-to-end shapes. Note: `executeReactive` comes from `@reactive-agents/reasoning` dist (fresh at 14:01 today; rebuild after reasoning src edits).

**Q2 (confirmed, with one prediction wrong).** `policyLLMLayer(model, seed)` routes by `request.purpose`, records every request, and returns turns reactively (the model reads the request: tools present or not). Token counts come from the recorded request (system + messages + tool JSON). Shape "partial answer with unread input", policy = reads the second input if it has tools, writes a partial reply if it has none:
- Named files (`a.json`, `b.json`): off and on both solve. The `unreadNamedInputs` gate holds the lean turn until both are read, then it fires once. Verdict neutral; on-arm agent input tokens 591 vs 647 off (-8.7%), 3 agent turns both. My prediction said "inert": wrong, the guard fires on the legitimate final turn.
- Inputs named in prose only ("the first report and the second report"): off solves (3 turns, 678 tok). On: lean turn fires after one read, the tool-less partial reply ("I still need the second report") is accepted as the final answer, run ends unsolved at 2 turns (354 tok). Verdict HURTS, deterministic. This is the defect `unreadNamedInputs` was added for, still open for inputs the file-token regex cannot see; the continuation-intent detector that would catch the reply was reverted in 62cf0c857. Real finding for the kernel owner (seam test pins only "Next I will check ..." continuation text, not "I still need ...").

**Q3 (confirmed).** Static `TestLLMService([{text},{toolCall},{text}])`: a `classify`-purpose call returns the first text turn and advances the cursor; the agent's first call then gets the toolCall, never the scripted text. The policy layer answers the same harness call `{}` and the agent script is untouched. Test-pinned.

**Q4 (feasible as a probe).** `prefixForkLayer(events, k, after)` (60 lines, on `buildSequentialLLMTable` + `makeReplayLLMLayer`): on `golden/tool-write.jsonl` (2 recorded calls) call 0 replays from the recording, call 1 comes from a policy; the live `file-write` tool wrote `note.md`; output is the substituted turn. Missing for a real prefix-fork probe: (a) fork point is a call index, not a trace state; no check the live harness reached the recorded state (blind replay); (b) `makeReplayLLMLayer.completeStructured`/`getModelConfig` die, so goldens with harness structured calls cannot be forked; (c) recorded exchanges store `toolSchemaNames` only, not schemas, so tool-schema tokens cannot be rebuilt from a trace; (d) `makeReplayAgent` has no LLM-layer or harness-config hook (the spike built the agent directly); (e) recorded tool mode erases the tool surface (known limit in `replay-agent.ts` header), so fork probes must use live tool mode with a scratch `fileRoot` (used `packages/benchmarks/.bench-run-s6`, gitignored, removed after).

**Q5 (confirmed).** Same seed twice: identical request logs (purpose, tool names, message counts, request tokens) and output on a full `executeReactive` run. Seeded rng is mulberry32; the policy here uses no randomness, so the stochastic tier's determinism is only shown for the plumbing, not yet for rng-driven policies.

## Verdict: PASS (build Phase Z)

No kill criterion hit. Nothing in `llm-provider`, `testing` or `runtime` has to change to start: the policy layer wraps `TestLLMService` one turn per call. Fixes that make it better (route to owners):
1. llm-provider/testing owner: optional `usage` from request size in `fakeUsage` (`testing.ts:77-84,316`), or export a `requestTokens` helper; make a `text` turn protected from harness calls (or document `policyLLMLayer` as the supported path).
2. replay owner (harness-warden, mine): `completeStructured`/`getModelConfig` support in `makeReplayLLMLayer`; fork-by-state (match on run state, not index); record full tool schemas (or a schema hash) in `llm-exchange` (trace schema, producing package's warden); LLM-layer + harness hooks on `makeReplayAgent`.
3. kernel-warden: lean-final-turn accepts a tool-less partial reply when an input is named in prose (the HURTS shape above). Needs a deterministic detector for a reply that declares an unmet need, or a gate on declared-input coverage that does not depend on filename tokens.
4. Not tested here: `ScenarioConfig`/`runCounterfactual` /tmp writes (not used by the spike).
