### B2: `resolveOllamaEndpoint` default test fails under the CI mirror (blocks the push, not publish)

### Blocker B3: root `bun test` fails a stream fixture with extra `ContextPressure` chunks

- **Test:** `packages/runtime/tests/sub-agent-stream.test.ts:162`, `runStream — sub-agent activity > full-density root-only chunk sequence is byte-identical to the pre-refactor fixture`.
- **Error:** `expect(received).toEqual(expected)`. The received sequence has two extra chunks: `{ _tag: "ContextPressure", level: "low", tokensUsed: 105, tokensAvailable: 7895, utilizationPct: 1.3125 }` after iteration 0's `TokenUsage`, and `{ tokensUsed: 156, tokensAvailable: 7844, utilizationPct: 1.95 }` after iteration 1's. The window is 8,000 tokens. The fixture `packages/runtime/tests/fixtures/root-only-stream.json` (last changed `ad1356461`, 2026-11-17) has no `ContextPressure` chunk.
- **Isolation result:** the test passes alone (11 pass) and with `bun test ./packages/runtime` in one process (3,042 pass, 0 fail). It also passes in `repo test --all`, because that runner splits the suite into chunks. It fails only in the full single-process root run. In that run, 1,858 test files execute before it. So state leaks across files from earlier in the root order.
- **Likely mechanism (not pinned):** the gauge emits only when `resolveContextWindow` (`packages/reasoning/src/kernel/utils/context-window-fallback.ts`) finds a real window. The scenario uses provider `test` and model `test-model`. The static table has only a `test/test` row, so the window must come from the process-wide `probedRegistry` in `packages/llm-provider/src/capability-resolver.ts` (tier 1). `registerUserSuppliedCapability` writes to it from `.withModel({ numCtx })` at build time. Nothing resets that registry: there is no clear or reset export. One candidate is new since Attempt 2. `packages/runtime/tests/seam-with-model-params.test.ts` (`6fb1cebcb`, the `withModel` overload) builds `.withModel("test-model", { numCtx: 8000 })` and does not clean up. In the mirror it ran before the failing file. But that file plus the failing file in one process **passed**, so it is not enough alone. Some earlier file must also put the provider id on the request so that the fallback resolves. The leak source still has to be pinned.
- **Fix direction (owners):** fix the boundary, not one test. (1) `provider-warden`: add a test-only reset for the probed-capability registry, or scope user-supplied rows so they cannot outlive a run. (2) `runtime-warden`: give `seam-with-model-params.test.ts` a unique model id and cleanup. Make the root-only fixture independent of registry state, for example by pinning the run's window or stripping `ContextPressure` the way `checklist: false` strips `ChecklistUpdated`. Fastest repro: `bun run repo ci --run 'bun test'`, or a single-process `bun test` over `apps/` plus `packages/` up to `packages/runtime`.
