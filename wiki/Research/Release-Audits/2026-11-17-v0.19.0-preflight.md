## Findings (not blockers)

### F1: `repo test` summary hides file-level errors

Chunk 4 printed `8273 pass, 0 fail, 2 skip` and exited 1. The raw log shows `0 fail` and `1 error` ("Unhandled error between tests"). The summary line drops the error count, so a reader of the summary sees a green suite with a non-zero exit. Owner: the repo-tool owner (`tools/repo/src/commands/test*`). Suggested fix: print `N error` in the summary and name the erroring file.

### F2: one `repo test packages` run exceeds the 600 s cap

A release gate that cannot run in one invocation needs a documented chunking (or a higher cap for `--all`). Owner: repo-tool owner.

### F3: install size vs v0.18.0

v0.18.0 baseline reproduced in a fresh dir: `npm install reactive-agents@0.18.0` gives **238 MB, 277 packages** (`npm ls --all --parseable`, minus root).

| Install | Size | Packages |
|---|---|---|
| `reactive-agents@0.18.0` from npm | 238 MB | 277 |
| local `reactive-agents` tarball (+ overrides to local `@reactive-agents/*` tarballs) | 243 MB raw | 254 |
| same, minus stale local chunks (estimate) | ~183 MB | 254 |
| clean-install project (all 35 tarballs, incl. cortex, UI bindings) | 289 MB | 318 |

The 243 MB raw figure is inflated by the local build, not by the release. `tsup.config.base.ts` sets `clean` only when `CLEAN=true`, so local `dist/` folders accumulate hashed `.d.ts` chunks across builds: `runtime` 101, `reasoning` 77, `tools` 11, `core` 3. 188 of them are unreferenced, about 60 MB. The published `@reactive-agents/runtime@0.18.0` has one chunk, which matches a fresh CI checkout. publish.yml builds from a fresh checkout, so the shipped v0.19.0 should be about 183 MB / 254 packages. That is roughly 55 MB and 23 packages smaller than v0.18.0. Third-party deps are smaller; `@reactive-agents/*` code is about the same size once the stale chunks are excluded.

Caveat: the clean-install smoke packs the local `dist/`, so locally it tests a superset of what ships. Running `CLEAN=true bun run build` before `test:install` would make the local measurement exact. Owner: whoever owns `tsup.config.base.ts` / `scripts/test-clean-install.ts` (escalate; release-warden does not edit scripts).

### F4: baseline versions differ across packages (expected, but worth knowing)

`release:dry` shows `@reactive-agents/cortex` and `@reactive-agents/cli` at `0.10.6` and the other 33 public packages at `0.18.0`. npm serves `0.18.0` for all of them, and release.ts stamps all 35 to `0.19.0`. This does not block the release. The mixed baseline means the post-release sync stamps `packages/*` but not `apps/*`.
