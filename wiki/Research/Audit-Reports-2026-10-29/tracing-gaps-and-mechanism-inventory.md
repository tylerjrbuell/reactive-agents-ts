## 4. Recommended unification (hypotheses unless marked)

North-star shape: one-directional Contract -> Ledger -> Assessment -> Control -> Actuators -> Projector. The recurring fault is that decision *outputs* leave the loop without a typed *record*; fixing that is cheaper and safer than merging guard logic first.

Sequenced by leverage:

1. **Trace emit boundary + typed decision records (H, leverage highest, effort M).** Introduce one `DecisionRecord {kind, inputs, outcome, alternatives, authority}` emitted from `terminate()` (terminate.ts:178), tool-surface finalization, and guards. Make `rationale` mandatory on `terminate()` (type-level) so the 20 sites cannot omit it. Everything in 2.3 P1-P4/P7/P12 hangs off this. Why first: it makes every later unification measurable and de-risks the rest. Pins needed: a test that fails when a `terminate(`/`emitGuardFired` site omits inputs ("wire it AND pin it").
2. **Single `ResolvedWireParams` (H, effort M).** One function computes numCtx (+source), outputBudget, window, promptTokens; kernel guard, projection window, gateway and Ollama provider all consume the same object (provider receives it on the request instead of recomputing `resolveOllamaNumCtx`). Kills D3 and gives T1. Needs provider-warden + kernel-warden dispatch.
3. **Deliverable single funnel (H, effort M).** One `selectDeliverable(state): {chosen, candidates[], rejected[]}` that all D1 call sites use; align `finalizeOutput` source vocab to the core 4-source type; apply `detectContinuationIntent` inside the selector as the commit-time invariant rather than per-path. Makes L5 impossible by construction and traced by T4.
4. **Guidance composer (H, effort M).** Replace the concatenation in think.ts:541-587 with `composeGuidance(sources[]) -> {text, provenance[]}` where every harness text producer returns `{id, priority, text, signalTarget?}`; every item opens a ledger signal (fixes 2.2 coverage by construction). Conflict rule: one directive per target tool/policy per turn.
5. **Guard arbitration widening (H, effort L, last).** Route loop-detector, low-delta, head-truncation, pace actions, checklist reminder proposals through `resolveControlPlane` so overlap is resolved once. Highest behavioral risk -> requires lift-gated ablation (project rule: >=3pp lift, <=15% tokens) before default-on.
6. **State sync to the model (H, effort S/M).** Todo and checklist truth: one projector section generated from the ledger (not model-edited state) shown every think, so `todo add` vs `done` mistakes are visible/self-correcting; trace `todoSeen` vs `todoTruth`.

Not recommended [H]: adding more detectors in `rax-diagnose` before steps 1-2; they would key off free-text `reason` strings.
