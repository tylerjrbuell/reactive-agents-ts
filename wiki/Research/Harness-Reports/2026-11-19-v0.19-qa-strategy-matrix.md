## Findings

### Release-blocking (NEW)

**N1. The repetition backstop blocks the 4th distinct-argument call in strategies with a small per-pass iteration budget (direct, reflexion).** Owner: kernel-warden.
- Evidence: the model issues six `city-population` calls with six different cities in one turn. Calls 1-3 run; calls 4-6 (Lima, Oslo, Cairo) return `⚠️ You have already called city-population 3 times. Stop repeating this tool.` (`repetition_guard` block). Seen in 6 traces on 2 models: gemini direct run0 `01M7T4H17TP5ZZ9QGBH64X0HC8`, direct run1 `01M7T4ZAZXB0383GM92AKH40JX`, reflexion run0 `01M7T4DTX245N6AYNV59TMQ7J5`, reflexion run1 `01M7T4WVR0C9ZGY50CMJ3V8M2N`; cogito:14b reflexion `01M7T5197CBF1K8JTG3AZWMVB8`, direct `01M7T5V7PG6DETHKE9XM93T6K2`. That is every direct and reflexion task-b run on both models (6/6). Reactive, PER, ToT and adaptive run the same six calls unblocked (6/6 in every run).
- Mechanism: `packages/reasoning/src/kernel/capabilities/act/guard.ts:645-655` sets `backstop = max(threshold, repetitionBackstopCalls(harness, maxIterations, callsPerIteration))`. `maxIterations` here is the pass budget (direct clamps to 3, `packages/reasoning/src/strategies/direct.ts:132`; a reflexion pass gets `run.iterationShare(...)` = 4, `reflexion.ts:250`), and `callsPerIteration` is 1 for a tool that is not in the parallel-safe set (`packages/reasoning/src/harness-config.ts:325-333`). So `ceil(3 * 0.75) * 1 = 3` and `ceil(4 * 0.75) * 1 = 3`: the distinct-arguments carve-out stops at call 4 even though all six arrived in one batch with distinct args and every result was new information. With `withMaxIterations(14)` a reactive run gets `ceil(14 * 0.75) = 11`, which is why it passes.
- Consequence: gemini direct ends `failed / guard_stop` (`dispatcher_early_stop` at iteration 2/3, `rax-diagnose cause`: `budget-cap/cap-cutoff`, evidenceDelta>0) 2/2. cogito direct answers honestly ("Lima: (data not available) ... I cannot provide a total") and is graded **`success`**: `rax-diagnose cause`: `none ... status=success authority=guard:dispatcher_early_stop`, `terminatedBy=controller_early_stop:dispatcher_early_stop`, `deliverable_decision=pass (verified)`. A guard-stopped run with an admitted-incomplete answer should not be `success` (owner: kernel-warden, shared terminal path). Reflexion fabricates the three blocked values (gemini run0: Tokyo 37,400,068 etc.; cogito: Lima 9,861,769, Oslo 693,494, Cairo 9,533,333). The block nudge ("try a different tool") also sends the model to `discover-tools` (N7), burning one of direct's three iterations.
- Fix direction (boundary, not per strategy): the backstop should count the calls the model actually batched in one turn and/or use the run budget, not the per-pass share. Pin with a direct-strategy test issuing 6 distinct calls of one custom tool in one turn.

**N2. Gemini provider drops `thoughtSignature`; reflexion's re-seeded passes get HTTP 400 from Gemini.** Owner: provider-warden.
- Evidence: `400 Function call is missing a thought_signature in functionCall parts. ... function call default_api:city-population, position 3` (and `discover-tools`, position 2/3). 4 of 4 reflexion improve-pass starts in 2 gemini task-b runs (`01M7T4DTX245N6AYNV59TMQ7J5`: 1; `01M7T4WVR0C9ZGY50CMJ3V8M2N`: 3). `rax-diagnose cause`: `provider-error, decisive`.
- Mechanism: no `thoughtSignature` / `thought_signature` string exists anywhere in `packages/llm-provider/src`. The response part type `packages/llm-provider/src/providers/gemini.ts:74-82` keeps only `{ name, args }` of a `functionCall`, and `packages/llm-provider/src/providers/gemini-messages.ts:62,124` rebuilds `functionCall` parts without the signature. Gemini 3-family thinking models require the signature to be echoed on function-call parts.
- Unverified: why reactive multi-turn calls (20+ runs here, two turns each) did not 400. Hypothesis: reflexion seeds a new pass with prior function-call parts in what Gemini treats as the current turn. Either way, any Gemini 3 model is one message-arrangement away from this 400.
- Fix direction: capture `thoughtSignature` on each `functionCall` part in both `complete()` and `stream()`, carry it on the tool-call record, and replay it in `gemini-messages.ts`.

**N3. Reflexion reports `success` after its last pass ends in `llm_error`, shipping an unverified (gemini run0: fabricated and truncated) draft.** Owner: kernel-warden.
- Evidence: both gemini task-b reflexion runs end with `run-completed status=success terminatedBy=llm_error`. `rax-diagnose cause`: `provider-error ... status=success authority=error`. In run0 the critic's last verdict was `UNSATISFIED: The response was truncated and failed to provide the populations for Oslo and Cairo...`, then the final improve pass 400'd (N2), and the run shipped that same truncated draft (`* **Lima:** 1,414,213\n* **Os`) with fabricated Tokyo/Paris/Lagos values as `outcome: success`. The `AgentResult` says `terminatedBy: "end_turn"` while the trace says `llm_error`: result and trace disagree.
- Mechanism: `packages/reasoning/src/strategies/reflexion.ts:553` `const newResponse = improvePass.output || s.response;` silently carries the prior draft through a failed pass. The status decision at `reflexion.ts:636-641` and the substrate cap then produce `completed`; an errored final pass never downgrades it.
- Relation to KNOWN K1: same strategy, different path (error pass, not the generate-pass cap). The K1 fix should be checked against this trace too.

### Release-blocking candidate, owner decision needed

**N5. `gemini-flash-latest` (any Gemini id not in the static table) runs at a 2048-token fallback context.** Owner: provider-warden.
- Evidence: every gemini trace has `capability-resolved source=fallback recommendedNumCtx=2048 supportsThinkingMode=false` and `projection-rendered window=2048`. The run prints a warning once.
- Mechanism: `packages/llm-provider/src/capability.ts:455-510` lists only `gemini-2.5-pro`, `-2.5-flash`, `-2.5-flash-lite`, `-3.5-flash`; no `-latest` aliases. `capability-resolver.ts:228-236` falls back.
- Plausible link (not proven): the owner's "larger Gemini runs go badly". A 2048 window makes the projector compress every context past about 8 KB; with thinking tokens unaccounted (`supportsThinkingMode: false`, output budget 2000), answers can truncate (N3's draft ended mid-list). Cortex's offline list uses 2.5-series ids, but Cortex lists live models from the API, so a user can pick `gemini-flash-latest` or a `-preview` id. Blocking if Cortex users pick those ids; the fix is small (alias rows, or a Gemini family rule).

### Non-blocking (NEW)

- **N4. Reflexion's "ALREADY COMPLETED ACTIONS" list is wrong.** Owner: kernel-warden. `reflexion.ts:793-813` marks an action failed only when its observation matches `/\[Tool error/`, so guard-blocked calls show as `✅` (`✅ city-population({"city":" Cairo"})` while Cairo was never fetched). It also pairs actions and observations by index, and it only sees the last tool-calling pass (`reflexion.ts:514,555`), not the values earlier passes got. Gemini run0's improve pass therefore had neither Tokyo's real value nor an accurate list of what was missing, and fabricated. Fix with N1; the fabrication needs both.
- **N6. Direct ends `failed` with gathered evidence it never answers.** `dispatcher_early_stop` at iteration 2/3 with `evidenceDelta > 0`; the error says the evidence is attached as `metadata.extensions.unfinishedEvidence`. Mostly a consequence of N1 + N7 here; with three iterations, any wasted turn leaves no turn to answer. Owner: kernel-warden (shared terminal path, per pitfall 12).
- **N7. `discover-tools` is shipped and called under a restrictive `allowedTools`, and replies "No tools are available to you in this run."** 4 gemini runs (reflexion, direct). The text misleads: it reads as "you have no tools". The repetition nudge ("try a different tool") points models at it. Owner: tools-warden. Earlier vetting already judged `discover-tools` pure cost (see MEMORY "Powerhouse vetting").
- **N8. code-action sandbox tool calls emit no `tool-call-start` / `tool-call-end` trace events**, only `ledger-entry` entries with `toolCallId: code-action-*`. Trace-based tool counts and `rax-diagnose` see zero tools for these runs (the probe counts ledger entries to compensate). Owner: kernel-warden (producer), trace reader unchanged.
- **N9. Needs repro: long-lived processes that run several agents stalled twice.** (1) The gemini task-a chunk stayed alive after its seven build/run/dispose cycles finished (about 88 s of runs, then killed at the 590 s timeout, exit 137). (2) In the cogito task-b chunk, tree-of-thought (the 4th agent in the process) made no LLM request for at least 5 minutes: at 10:05 `ollama /api/ps` showed no model loaded and the process had used 3 s of CPU since 09:57. It was killed, so no trace was flushed. The same ToT cell run alone finished in 166 s, correct, 16 LLM calls. Single runs of reactive, code-action and tree-of-thought (with and without web-search) each exit within 10 s after `dispose()`. A third multi-agent process (cogito task c, 7 agents) did not stall. Not blocking on this evidence, but Cortex is a long-lived multi-agent server: owner runtime-warden should try a repro (one process, 10+ sequential agents with tools, then check for pending fibers or timers after `dispose()`). The probe now ends with `process.exit(0)`.

- **N10. Instrument fault: `rax-diagnose` blames the environment for N1.** Owner: harness-warden (`packages/diagnose`, out of this mission's write scope). `attribute --all` over the 28 gemini runs: 4 failed, `environment:budget-cap` 2, `environment:provider-error` 1, `harness:evidence-truncated` 1. The two direct failures are `budget-cap/cap-cutoff` with advice "raise the iteration budget", but direct cannot go above 3 iterations and the cause is the three `repetition_guard` blocks in the same trace. Attribution should rank a `repetition_guard` block on a distinct-argument call, made before a cap stop, as harness. Per the ownership rule, the fix re-runs `attribute --all` on the reference corpora and reports the before/after table.

- **N11. code-action failure text and stdout are misleading.** cogito task b (`01M7T5VW73ZACJVY5DCPXF1598`): after one LLM call, the model's program printed `Tokyo: [object Object] ... Total population: 0[object Object]...`, and that print reached the host process stdout. The run correctly ends `failed`, but its error reads `Could not complete the task within the available budget`, which blames the budget for a bad program. `rax-diagnose cause`: `unexplained`. Owner: kernel-warden (code-action); low.
