## Next harness reasons, ranked

### N6. The reparse hint teaches a call form the parser rejects (tools-warden), 6 runs

`assistant-text-parser.ts:85` builds the hint as `call it on its own: ${name} ${JSON.stringify(args)}`, which gives `file-read {"path":…}`. None of the parser tiers (`assistant-text-parser.ts:398-426`: taught markup, dialect markers, JSON, `name(args)`, CLI) reads that form. `detectToolCallShape` does not flag it either, so the turn returns `none`.

**Zero-token check (`parseprobe.ts`).** I fed the recorded replies to `parseAssistantToolCalls`, and also the bare substring `http-get {"url":"https://jsonplaceholder.typicode.com/posts?userId=3"}`. Every input returned `none`.

**Effect.** The model copies the hint verbatim. The call never runs, and the turn is not tagged unresolved, so the strike count silently resets and the run loops until the grounding gate abstains.

**Frequency.** 13 echo turns in 6 cogito runs, 0 executed, all 6 failed:
- `01M6RZ3KA3C4JQDG0QX3WTVQC8`
- `01M6RZ7MGR3MBYZS1BZ62KVB9R` (abstained)
- `01M6RZAD1KP7CMRQ914BW2MCG2`
- `01M6S0MR1Q3XWTHT0PRE3W87MZ` (abstained)
- `01M6S0TN86H91WD3QXFT9016FS`
- `01M6S0ZR0Z4Q7ZT0K06164PZJB` (abstained)

The hint was invisible before `49cbecf72` (0 requests), so this is newly live.

**Fix direction.** A hint must round-trip. Pin `parse(hintForm(args))` as `parsed`, and either word the hint in a form a tier accepts or add a standalone `name {json}` tier on the same argument grammar. This is one fix, and the most deterministic one on the list.

### N7. Tools stay withheld after a compliant prose reply (kernel-warden), 2 runs

`01M6S0G3MH67SZVWTGMPGAF11Y` and `01M6S0X3ZCH05VP1KRDPMQXTX5` (cogito rw-4 r0, r2) follow the same sequence:
1. Tools are withheld at iteration 2, and the model answers in prose.
2. At iteration 3 tools return with a grounding steer, and the model prints call text.
3. Tools are then withheld at iterations 4, 5 and 6 in a row, and the model answers in prose each time.
4. The run ends `abstained`: there is no tool success, and with no tools offered there cannot be one.

`think.ts:195` documents "withhold tools for one call". But `shouldWithholdTools` (`unresolved-tool-call.ts:119-120`) reads `countUnresolvedSinceSuccess` (`reflect/unresolved-steps.ts:66-73`), which only a successful tool observation resets.

Status: probable. Why iteration 3 was not withheld needs a replay. Before N1 these runs died at strike 3, so the trap was invisible.

### N5. Plan-execute vetoes a verified delivery over a step-scoped `answer` (kernel-warden), 2 runs

`01M6RY6SZ972VRSASFNHKYW1C2` and `01M6RYHFQWS8EVT19BK6XQJGQV` (qwen plan-only r2, r4) both look like this:
- Hidden check: `score=1.000 passed=true`.
- `run-completed`: `deliverable.accepted=true`, verifier `verified=true`, `outstanding:["answer"]`, `authority: runtime-success-veto:outstanding-criteria`, `kernelAuthority: envelope-outstanding`. Status: failure.

**Cause, located but not traced end to end.** The composite read step's own pass ended with a refused handoff synthesis, so its envelope carries `answer` outstanding. `strategy-run.ts:583-595` joins every contributing pass worst-of. It then forwards that step-scoped outstanding through `honestEnvelopeMetadata` to the run, and `execute-success-invariants.ts:141-148` vetoes. `completion-envelope.ts:271` says `outstandingCriteria` "is step-scoped".

**Trigger.** The planner emitted `toolArgs: {}` for the read step in 3/5 qwen runs after, against 0/5 before. That is model variance, and it routes the step to a composite.

### Instrument faults (`packages/trace`, not fixed under this brief)

- **(c)** The 4 LH abstained runs from N6 and N7 are labeled `model:ignored-guidance`. In 2 of them (N6) the model followed the harness's hint verbatim and the parser dropped the call. In the other 2 (N7) the model obeyed the plain-text instruction and the harness kept tools withheld. Attribution should check a reply against the hint it echoes, and check the tool surface across the final turns, not only the turn of the guidance.
- **(d)** `harness:false-veto` on `01M6RZ0P…` counts a run that delivered files but no answer as a harness fault. Whether a missing answer on a file task is a harness or a model loss needs an owner decision.
- **(e)** The repetitionGuard pass path records no carve-out id (converging / superseded / distinct-target), so `b37faa30a` cannot be credited per call. This is a producer-side event field, so it stays with the kernel warden.
