## Deviations from the brief (read first)

1. **Tiers are not llama3.2:3b + a gemma.** The bench's capability-source preflight (`src/preflight.ts`) marks any model absent from `STATIC_CAPABILITIES` as `source="fallback"` (2048-token ctx) and every cell INCONCLUSIVE. Measured: `llama3.2:3b`, `gemma4:e4b`, `gemma4:12b`, `cogito:3b` all fall back; `qwen3:4b`, `cogito:8b`, `qwen3.5:latest`, `qwen3.8:27b`, `gemma4:26b` are trusted. `RA_BENCH_ALLOW_FALLBACK=1` would run at 2048 ctx and void the baseline, so it was not used. Chosen: small = `qwen3:4b`, mid = `cogito:8b` (the bench's standing local model, `bench:baseline`).
2. **Real-world task subset.** Brief says "the existing 5 real-world tasks". `rw-1`/`rw-4` need live network (not freezable); `rw-5`/`rw-8`/`rw-10` are judge-graded or compaction-length with no deterministic grader. Frozen: `rw-2, rw-3, rw-6, rw-7, rw-9` (their `dimensionRubrics`/`primaryDimensions` stripped so no judge is ever consulted; ids kept because `dispatch` keys the rw-9 flaky-server on `task.id`). Plus `ab-trap-4`, `ab-trap-5` (deterministic `scoreAbstention`).
3. **MCP-wide: DEFERRED** (no local MCP server practical offline; H1 owns the umami/MCP 5-task set).
4. **todo-heavy cannot exercise the `todo` meta-tool.** Instrument check: the `todo` tool is not on the tool surface under the default path NOR under `.withMetaTools()` (adds only brief/pulse/find). The bench `HarnessConfig.metaTools` is a boolean and cannot express `withMetaTools({todo:true})`. The task is a todo-heavy WORKLOAD (six independent items), but K2's change surface (todo-iteration stall accrual) is not reachable from H3 yet. Needs a bench-seam widening (see Findings).
5. **Edit-tool constraint.** No Edit/Write tool was available in this session, so no existing file was modified. The H3 runner swaps its judge-stripped tasks into `ALL_TASKS` in-process (`registerH3Tasks`) instead of the cleaner `BenchmarkSession.tasks` seam. That seam is a 2-line change in `runner.ts`/`types.ts` for the parent (patch in Findings).
6. **Timeouts count as unsolved.** The runner flags a wall-clock `execution-timeout` cell `inconclusive` and would drop it from the denominator. H3 keeps those as measured failures (policy declared before any outcome was read; `isMeasured` in `report.ts`, tested). 2 timeouts total, both qwen3:4b (rw-7 run 1, todo-heavy run 2). ## Feedback loop: grader-in-trace (added 2026-11-03, after the baseline)

The `cause labels` column above says how a run ENDED, never whether its answer was right, so 28 of the 64 unsolved runs read `none`. The deterministic grade now rides the run's own trace:

- `packages/trace`: new `eval-graded` trace event (`score`, `passed`, `threshold`, `checks[]`, `grader`, `taskId`, `suiteHash?`, `source`). New cause `wrong-answer`: only in the clean-ending residual (a run that would be `none` or `success-with-warning`) whose last `eval-graded` has `passed=false`. Decisive; `subCause` = first failed check. A passing grade never changes a label; every process rule still wins.
- `packages/benchmarks`: `runSession` appends the grade to each trace right after `scoreTask` (deterministic graders only; judge-scored and inconclusive accuracy record nothing). `scoreVerifiable` now keeps every hidden-check `FAIL:` line as a named check (the 200-char evidence string used to lose them). `run-h3.ts` stamps `h3SuiteHash()`.
