## 0. What the data says

Measured on 112 content pages (2026-11-17):

- The sidebar already lists 109 of the 110 pages other than home and the 404 page. Only `/guides/plan-then-execute/` is missing. Orphans (no sidebar entry, no inbound link): 0. So "scattered" is not about hidden pages. It is about **where** pages sit and **how many near-copies** exist.
- 4 pages have zero inbound content links and are reachable only through the sidebar: `/concepts/agent-lifecycle/`, `/cookbook/status-display/`, `/guides/introduction/`, `/telemetry/`. The introduction page, first item of Get Started, has no inbound link from any page.
- Click depth from home is shallow only because of the sidebar: median 2, max 3 with the sidebar counted, but 4 pages are unreachable by content links alone and `/cookbook/local-agent-ollama/` is link-depth 7. A reader who does not use the sidebar cannot navigate the site.
- The top-level directories are not the IA. Sidebar group and directory disagree often: `features/` holds capability pages, concept pages, Cortex, evaluation and operations pages; `guides/` holds tutorials, comparisons and the changelog. The sidebar "How It Works" group mixes concepts (architecture), a product (Cortex Studio, 13 pages) and runtime features (verification, resilience).
- 2 pages appear in 2 sidebar groups (`/cookbook/chat-and-sessions/`: Build and Cookbook; `/reference/cli/`: API Reference and Rax CLI).
- 7 pages exceed 3,500 words (sizes in section e). Together they hold 50k of the 197k words.
- Near-duplicate analysis (shingle containment, thresholds in the inventory) finds little verbatim copy-paste outside Cortex. The duplication is semantic: several pages answer the same question in different words. Section 1 lists the clusters.
- 34 internal links lack a trailing slash (19 in what's-new alone). They work but force a redirect hop; fix them in stage 1.
- 0 of 112 pages carry `topic` or `related` frontmatter, so there is no machine-readable grouping yet.

Decision rule used below: **URLs are an asset. Change the sidebar freely, move a file only when the old location teaches the wrong thing, and every move gets a redirect.** Only 6 pages move or merge; 7 split (the original URL stays on the page that keeps the overview).

## c. Frontmatter schema, Related block and breadcrumb

Add three optional keys through `docsSchema({ extend })` in `apps/docs/src/content.config.ts` (a content-collection change, owned by this warden in a later mission):

```yaml
topic: tools            # one value from the controlled list below; exactly one per page
related: [guides/mcp-tools, cookbook/building-tools]   # 0-4 slugs, order = display order
audience: builder       # optional: starter | builder | operator | contributor
```

Controlled `topic` list (derived from the clusters in section 1): `getting-started`, `reasoning`, `tools`, `mcp`, `memory`, `providers`, `local-models`, `streaming`, `context`, `agents` (sub-agents, skills, hooks), `channels`, `gateway`, `web-ui`, `durable-runs`, `safety`, `cost`, `observability`, `quality`, `cortex`, `cli`, `config-reference`, `concepts`, `compare`, `releases`, `help`.

How they are used:

- **Related block.** The existing `Footer` override renders "Related" from `related` (explicit list, max 4). If `related` is empty it falls back to the other pages sharing the `topic`, sorted by sidebar order, max 4. Each link carries an Umami event (`docs_related_click`, to be added to `wiki/Reference/Umami-Events.md`). This replaces hand-written "What's Next" lists, which today point to different pages from the sidebar's next item (rule 3).
- **Breadcrumb.** `PageTitle` renders `Group > Subgroup` from the page's sidebar position (Starlight exposes it in `starlightRoute.sidebar`), so the breadcrumb always agrees with the sidebar. A page in no sidebar group renders no breadcrumb, which the gate reports as a warning.
- **Search and llms.txt.** `topic` is added to the Pagefind metadata so search results can be filtered by topic.
- **Gate (report-only now, enforcing later).** `bun run docs:sync:check` prints warnings for orphans, duplicate titles and pages missing `topic`/`related`. After stage 2 of the migration the missing-`topic` rule flips to a failure.
