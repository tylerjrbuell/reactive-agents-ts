The `@reactive-agents/benchmarks` package is an **internal evaluation harness**: a fixed set of tasks spanning 5 complexity tiers (trivial, simple, moderate, complex, expert) that you run against a real LLM to measure pass rate, latency, token usage, and cost for *your* provider and model choices.

We use it as development tooling to catch regressions; we don't publish its scores as marketing claims. Run it yourself against your own stack: the numbers that matter are the ones from your provider, your model, and your tasks.

The package is private (not published to npm), so you run it from a clone of the repository.

## What the Tasks Are

The tasks are hand-written prompts in `packages/benchmarks/src/task-registry.ts`. Some are modeled on the kinds of problems found in public benchmarks such as HumanEval, BIG-Bench Hard, SWE-bench, GAIA, and AgentBench. They are **not** samples from those benchmarks, and their scores are not comparable to published results on them.

Each task pins its reasoning strategy: trivial and simple tasks run single-shot, and moderate, complex, and expert tasks run `reactive`, `plan-execute-reflect`, or `tree-of-thought` depending on the task.

## Scoring

Most tasks are scored by a keyword check: a task **passes** if the output matches any one alternative of a case-insensitive regex. For example:

```
SQL injection fix expected: "parameteriz|prepared|placeholder|\$1|\?|injection|sanitiz"
```

This is a coarse smoke check. A loosely related answer can match one alternative, so treat a pass as "on topic", not "correct".

Five code tasks are instead graded by a hidden check that imports and runs the agent's code. That grading runs only in session mode (`--session`).

<Aside type="caution" title="Quick mode does not grade the code tasks">
In quick mode (`--provider` without `--session`), the five hidden-check tasks currently report pass without being checked. Treat quick-mode pass rates as a smoke test, not a measurement.
</Aside>

## Running Benchmarks

```bash
git clone https://github.com/tylerjrbuell/reactive-agents-ts
cd reactive-agents-ts
bun install
cd packages/benchmarks

# Quick mode: run the task set against one provider
bun run src/run.ts --provider anthropic --output report.json

# Run with a specific model
bun run src/run.ts --provider anthropic --model claude-opus-4-8 --output report.json

# Run only trivial + simple tiers (quick sanity check)
bun run src/run.ts --provider anthropic --tier trivial,simple

# OpenAI
bun run src/run.ts --provider openai --model gpt-4o --output report.json

# Gemini
bun run src/run.ts --provider gemini --model gemini-2.5-flash --output report.json
```

Named sessions (multiple models, harness variants, repeated runs, graded scoring) live in `packages/benchmarks/src/sessions/` and run with `--session <id>`.

### CLI Options

| Flag | Description | Default |
|------|-------------|---------|
| `--provider` | LLM provider (`anthropic`, `openai`, `gemini`, `groq`, `xai`, `ollama`, `litellm`, `test`) | `anthropic` |
| `--model` | Model name (uses provider default if omitted) | Provider default |
| `--tier` | Comma-separated tier filter | All tiers |
| `--task` | Comma-separated task IDs | All tasks |
| `--output` | Path to save JSON report | _(none)_ |
| `--session` | Run a named session instead of quick mode | _(none)_ |

### Provider Defaults

| Provider | Default Model |
|----------|--------------|
| `anthropic` | `claude-haiku-4-5` |
| `openai` | `gpt-4o-mini` |
| `gemini` | `gemini-2.5-flash` |
| `ollama` | `llama3.2` |

## Reading the Report

Pass `--output report.json` to persist a full JSON report (per-task pass/fail, latency, token usage, and cost) for your own analysis. Without `--output`, results print to the console and nothing is persisted.

## Where Our Own Measurements Live

The project's own measurements (ablations, harness reports, and the model and task counts behind them) are committed to the repository under [`wiki/Research/`](https://github.com/tylerjrbuell/reactive-agents-ts/tree/main/wiki/Research). One example: the [strategy-switching ablation](https://github.com/tylerjrbuell/reactive-agents-ts/blob/main/wiki/Research/Ablations/2026-11-05-strategy-switching-ablation.md) that turned that feature off by default.
