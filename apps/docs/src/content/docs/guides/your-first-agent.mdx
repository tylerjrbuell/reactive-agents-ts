This guide walks through building a research assistant agent with memory, reasoning, and guardrails.

<Aside type="note" title="Same API, two syntaxes">
`createAgent(config)` (declarative) and the fluent `ReactiveAgents.create().withX()`
(builder) are the same API — same names, same nesting. Every example below shows
both; flip the tab to your preference. Reach for the builder when construction is
conditional or imperative. The fluent equivalents are covered in the
[Builder API reference](/reference/builder-api/).
</Aside>

## The front door: `createAgent(config)`

Every agent starts from a declarative config object — the shape you know from the
Vercel AI SDK and OpenAI SDK:

<Tabs>
  <TabItem label="Declarative">
```typescript
import { createAgent } from "reactive-agents";

const agent = await createAgent({
  name: "research-assistant",
  provider: "anthropic",
  model: "claude-sonnet-4-6",
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
import { ReactiveAgents } from "reactive-agents";

const agent = await ReactiveAgents.create()
  .withName("research-assistant")
  .withProvider("anthropic")
  .withModel("claude-sonnet-4-6")
  .build();
```
  </TabItem>
</Tabs>

This creates a minimal agent with:
- LLM provider (Anthropic, Claude Sonnet 4)
- Direct LLM loop (no reasoning strategy, no memory, no tools)

## Adding Memory

Memory persists context across conversations:

<Tabs>
  <TabItem label="Declarative">
```typescript
import { createAgent } from "reactive-agents";

const agent = await createAgent({
  name: "research-assistant",
  provider: "anthropic",
  model: "claude-sonnet-4-6",
  memory: { tier: "standard" },          // 4-layer memory (default tier)
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
import { ReactiveAgents } from "reactive-agents";

const agent = await ReactiveAgents.create()
  .withName("research-assistant")
  .withProvider("anthropic")
  .withModel("claude-sonnet-4-6")
  .withMemory({ tier: "standard" })      // 4-layer memory (default tier)
  .build();
```
  </TabItem>
</Tabs>

The 4-layer memory system has two tiers:

| Tier         | Layers active                                      | When to use                                |
|--------------|----------------------------------------------------|--------------------------------------------|
| `"standard"` | Working + Episodic + FTS5 keyword search           | Conversational agents, default for most apps |
| `"enhanced"` | All 4 layers + vector embeddings (semantic recall) | Research agents, long-running tasks needing semantic similarity |

<Tabs>
  <TabItem label="Declarative">
{/* docs-skip-typecheck */}
```typescript
memory: { tier: "enhanced", dbPath: "./data/memory.db" }   // Full 4-layer
```
  </TabItem>
  <TabItem label="Builder">
{/* docs-skip-typecheck */}
```typescript
.withMemory({ tier: "enhanced", dbPath: "./data/memory.db" })   // Full 4-layer
```
  </TabItem>
</Tabs>

`"enhanced"` requires an embedding provider — set `EMBEDDING_PROVIDER=openai` or `EMBEDDING_PROVIDER=ollama` in `.env`.

## Adding Reasoning

The reasoning layer gives your agent structured thinking:

<Tabs>
  <TabItem label="Declarative">
```typescript
const agent = await createAgent({
  name: "research-assistant",
  provider: "anthropic",
  model: "claude-sonnet-4-6",
  memory: { tier: "standard" },
  reasoning: {},  // ReAct loop: Think -> Act -> Observe (pass { defaultStrategy } to switch)
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
const agent = await ReactiveAgents.create()
  .withName("research-assistant")
  .withProvider("anthropic")
  .withModel("claude-sonnet-4-6")
  .withMemory({ tier: "standard" })
  .withReasoning()  // ReAct loop: Think -> Act -> Observe (pass { defaultStrategy } to switch)
  .build();
```
  </TabItem>
</Tabs>

With reasoning enabled, the agent uses a ReAct loop instead of a simple LLM call. It can:
- Break tasks into steps
- Request tool calls
- Observe results and adjust

To switch strategy, pass `reasoning: { defaultStrategy: ... }` (declarative) or `.withReasoning({ defaultStrategy: ... })` (builder) — valid values are `"reactive"` (the default), `"plan-execute-reflect"`, `"reflexion"`, `"tree-of-thought"`, `"adaptive"`, `"direct"`, `"code-action"`, and `"blueprint"`. See [Choosing a Strategy](../choosing-strategies/).

## Adding Safety

Guardrails protect against prompt injection, PII leakage, and toxic content:

<Tabs>
  <TabItem label="Declarative">
```typescript
const agent = await createAgent({
  name: "research-assistant",
  provider: "anthropic",
  model: "claude-sonnet-4-6",
  memory: { tier: "standard" },
  reasoning: {},
  guardrails: {},         // Input/output safety
  costTracking: {},       // Budget controls
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
const agent = await ReactiveAgents.create()
  .withName("research-assistant")
  .withProvider("anthropic")
  .withModel("claude-sonnet-4-6")
  .withMemory({ tier: "standard" })
  .withReasoning()
  .withGuardrails()       // Input/output safety
  .withCostTracking()     // Budget controls
  .build();
```
  </TabItem>
</Tabs>

## Running the Agent

Once built, the agent is the same object either way — run it identically:

```typescript
const result = await agent.run("Explain the difference between TCP and UDP");

console.log(result.output);       // The agent's response
console.log(result.success);      // true
console.log(result.metadata);     // { duration, cost, tokensUsed, stepsCount }
```

## Reading the result

`run()` resolves to a result for nearly every failure mode — it throws only
when the run is interrupted (`agent.terminate()` / a kill-switch), plus one
legacy asymmetry noted at the end. Read the fields in this order:

1. **`result.status`** — `"awaiting-approval"` / `"awaiting-interaction"` means
   the run **paused**, not finished. Handle the gate (`approveRun()` /
   `denyRun()` / `respondToInteraction()`, or pass `onApproval` to `run()`);
   `"failed"` means the run ended without an accepted outcome.
2. **`result.success`** — whether the run terminated with an accepted outcome.
   `false` is not an exception: read `result.error` and `result.terminatedBy`
   off the result.
3. **`result.terminatedBy`** — how the loop ended: `final_answer_tool`,
   `final_answer`, `max_iterations`, `end_turn`, `llm_error`, or `abstained`.
   When `abstained`, `result.abstention` carries the reason and what was missing.
4. **`result.goalAchieved`** — the semantic readout: `true` delivered a final
   answer, `false` exhausted/errored/declined, `null` ambiguous (the model
   stopped its turn without signaling — treat as "maybe").
5. **`result.receipt?.verdict`** — an evidence grade for *how* the answer was
   produced (`"tool-grounded"` … `"failed"`), not a truth certificate for the
   answer itself.

The one asymmetry: a **bare builder** — an agent created without enabling
reasoning (no `.withReasoning()`, no declarative `reasoning` config) — **throws**
instead of returning a result when a run hits `llm_error` or `max_iterations`.
The same faults on a reasoning-enabled builder return
`{ success: false, status: "failed" }`. Unifying the two contracts is deferred
to a future breaking release; until then, wrap `run()` in `try/catch` whenever
the builder might be bare. The full ordered procedure, with code anchors for
every field, is in the
[Builder API reference](/reference/builder-api/#how-to-tell-what-happened-the-decision-procedure).

## Using the Effect API

For advanced use cases, use the Effect-based API (builder-only):

```typescript
import { Effect } from "effect";
import { ReactiveAgents } from "reactive-agents";

const program = Effect.gen(function* () {
  const agent = yield* ReactiveAgents.create()
    .withName("research-assistant")
    .withProvider("anthropic")
    .withReasoning()
    .buildEffect();

  const result = yield* agent.runEffect("Explain quantum entanglement");
  return result;
});

const result = await Effect.runPromise(program);
```

## Lifecycle Hooks

Observe and modify agent behavior at any phase. Hooks take functions, so they are
registered on the builder (no declarative config equivalent):

```typescript
const agent = await ReactiveAgents.create()
  .withName("research-assistant")
  .withProvider("anthropic")
  .withHook({
    phase: "think",
    timing: "after",
    handler: (ctx) => {
      console.log(`[think] Response: ${ctx.metadata.lastResponse}`);
      return ctx;
    },
  })
  .build();
```

Effect is optional here — a hook handler can return a plain value (or nothing, to just observe), a `Promise`, or an `Effect`; no `effect` import needed.

Available phases: `bootstrap`, `guardrail`, `cost-route`, `strategy-select`, `think`, `act`, `observe`, `verify`, `memory-flush`, `cost-track`, `audit`, `complete`.

Each phase supports `before`, `after`, and `on-error` timing.

## Testing

Use `withTestScenario()` for deterministic tests — it automatically sets the provider to `"test"`, so no API key or real LLM call is involved. Test scenarios are builder-only (turns are code, not JSON):

```typescript title="src/agent.test.ts"
import { expect, test } from "bun:test";
import { ReactiveAgents } from "reactive-agents";

test("answers deterministically", async () => {
  const agent = await ReactiveAgents.create()
    .withName("test-agent")
    .withTestScenario([
      { match: "capital of France", text: "Paris is the capital of France." },
      { match: "quantum", text: "Quantum mechanics describes nature at the atomic scale." },
    ])
    .build();

  const result = await agent.run("What is the capital of France?");
  expect(result.output).toContain("Paris");
});
```
