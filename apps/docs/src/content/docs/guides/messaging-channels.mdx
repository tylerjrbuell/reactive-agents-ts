Reactive Agents sends and receives messages on **Signal** and **Telegram** through **native channel adapters** from `@reactive-agents/channels`. An adapter owns its platform: inbound messages, outbound sends, sender identity, delivery receipts and reconnect. `ChannelService` consumes it, applies access control, runs the agent and sends the reply itself, so every reply has a real platform message id (or a typed `ChannelError`) instead of depending on the model to call a send tool.

| Platform | Native adapter | Transport |
|----------|----------------|-----------|
| Signal | `SignalChannelAdapter` | `signal-cli` JSON-RPC (daemon socket or spawned process) |
| Telegram | `TelegramChannelAdapter` | Bot API with a BotFather token (long polling or webhook) |
| HTTP | `WebhookChannelAdapter` | HMAC-signed webhook requests |

See [Signal (native)](/guides/messaging-channels/signal/) and [Telegram (bot)](/guides/messaging-channels/telegram/) for setup, then register the adapters:

```typescript
import { Redacted } from "effect";
import { ReactiveAgents } from "@reactive-agents/runtime";
import { TelegramChannelAdapter } from "@reactive-agents/channels";

const telegram = new TelegramChannelAdapter({
  token: Redacted.make(process.env.TELEGRAM_BOT_TOKEN ?? ""),
});

const builder = ReactiveAgents.create()
  .withName("telegram-agent")
  .withProvider("anthropic")
  .withChannels({ adapters: [telegram] })
  .withGateway({
    accessControl: {
      accessPolicy: "allowlist",
      allowedSenders: ["telegram:123456789"], // platform:userId
    },
  });
```

To write an adapter for another platform, see the [Channel Adapters guide](/guides/channel-adapters/). To run the agent unattended, see [Deploying Agents](/guides/deploying-agents/).

## The Channel Adapter Contract

The legacy Signal and (personal-account) Telegram setups are MCP servers: the agent reads and replies by calling tools, so delivery is whatever the model decides to do. `@reactive-agents/channels` defines the replacement: one `ChannelAdapter` contract every platform implements. The webhook adapter, the native Signal adapter and the Telegram bot adapter ship on the new contract today.

An adapter owns its platform (inbound, outbound, identity, receipts, reconnect), and `ChannelService` sends replies itself and gets real delivery receipts, typed failures and honest connection status. The full contract (the shapes, error kinds and what `ChannelService` does with an adapter) lives in the [Channel Adapters guide](/guides/channel-adapters/#the-contract). The pages above cover the shipped adapters.
