This checklist covers the builder methods and configuration options you should evaluate before deploying a Reactive Agents application to production. Each section is independent — enable the layers that match your threat model and reliability requirements.

<Aside type="caution" title="Before you ship">
Three settings are non-negotiable for any production agent: a **budget cap** (`.withCostTracking()`), an **iteration limit** (`.withBehavioralContracts({ maxIterations })`), and **structured logging** (`.withLogging()`). Without these, a single misbehaving prompt can drain a wallet, loop forever, or fail silently.
</Aside>

## Security

### Guardrails

Guardrails screen every prompt and response for prompt injection, PII leakage, and toxic content. Enable with `guardrails: {}` (declarative) or `.withGuardrails()` (builder). Each detector can be toggled independently; pass a `customBlocklist` to reject additional phrases.

<Tabs syncKey="syntax">
  <TabItem label="Declarative">
```typescript
import { createAgent } from "reactive-agents";

const agent = await createAgent({
  name: "prod-agent",
  provider: "anthropic",
  guardrails: {
    injection: true,
    pii: true,
    toxicity: true,
  },
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
const agent = await ReactiveAgents.create()
  .withProvider("anthropic")
  .withGuardrails({
    injection: true,
    pii: true,
    toxicity: true,
  })
  .build();
```
  </TabItem>
</Tabs>

A `GuardrailViolationDetected` event is emitted on the EventBus whenever a check fires, so violations surface in your observability pipeline automatically.

### Behavioral Contracts

Behavioral contracts constrain what the agent is allowed to do at runtime. Use a tool deny list to block dangerous tools, cap iterations, and restrict output patterns. This one is builder-only — `withBehavioralContracts` has no declarative `AgentConfig` key:

```typescript
const agent = await ReactiveAgents.create()
  .withProvider("anthropic")
  .withBehavioralContracts({
    deniedTools: ["shell-execute"],
    maxIterations: 20,
    maxToolCalls: 40,
  })
  .build();
```

### Tool Approval Gates (human-in-the-loop)

Gate high-risk tool calls behind human approval: name the tools in `.withApprovalPolicy()`, and add `.withDurableRuns()` when the pause must survive process death. The setup, the approve and deny calls and the live-versus-durable modes are on one page, [Durable Human-in-the-Loop](/guides/durable-hitl/).

> The per-tool `requiresApproval: true` flag is metadata only. It does not by
> itself pause a run. Use `.withApprovalPolicy({ tools: [...] })` to gate.

### Tool Allowlist

Restrict the agent to a fixed set of tools. Any tool not in the list is invisible to the LLM and cannot be called, regardless of what the model requests.

<Tabs syncKey="syntax">
  <TabItem label="Declarative">
```typescript
import { createAgent } from "reactive-agents";

const agent = await createAgent({
  name: "prod-agent",
  provider: "anthropic",
  tools: { allowedTools: ["web-search", "file-read"] },
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
const agent = await ReactiveAgents.create()
  .withProvider("anthropic")
  .withTools({ allowedTools: ["web-search", "file-read"] })
  .build();
```
  </TabItem>
</Tabs>

## Reliability

### Kill Switch

The kill switch enables programmatic lifecycle control. Call `agent.stop()` to end the run within about 100 ms (it is watched inside the reasoning loop and during model calls), or `agent.terminate()` for an immediate halt through the run's abort signal.

<Tabs syncKey="syntax">
  <TabItem label="Declarative">
```typescript
import { createAgent } from "reactive-agents";

const agent = await createAgent({
  name: "prod-agent",
  provider: "anthropic",
  features: { killSwitch: true },
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
const agent = await ReactiveAgents.create()
  .withProvider("anthropic")
  .withKillSwitch()
  .build();
```
  </TabItem>
</Tabs>

Then wire graceful stop from a signal handler or timeout:

```typescript
process.on("SIGTERM", () => agent.stop());
```

### Max Iterations

The default iteration cap is 10. Increase it for complex multi-step tasks, or lower it for latency-sensitive paths.

<Tabs syncKey="syntax">
  <TabItem label="Declarative">
```typescript
import { createAgent } from "reactive-agents";

const agent = await createAgent({
  name: "prod-agent",
  provider: "anthropic",
  execution: { maxIterations: 20 },
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
const agent = await ReactiveAgents.create()
  .withProvider("anthropic")
  .withMaxIterations(20)
  .build();
```
  </TabItem>
</Tabs>

### Execution Timeout

Set a wall-clock timeout in milliseconds. The agent throws a `TimeoutError` if the run does not complete within the limit.

<Tabs syncKey="syntax">
  <TabItem label="Declarative">
```typescript
import { createAgent } from "reactive-agents";

const agent = await createAgent({
  name: "prod-agent",
  provider: "anthropic",
  execution: { timeoutMs: 60_000 }, // 60 seconds
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
const agent = await ReactiveAgents.create()
  .withProvider("anthropic")
  .withTimeout(60_000) // 60 seconds
  .build();
```
  </TabItem>
</Tabs>

### Retry Policy

Configure automatic retries on transient failures (network errors, rate limits). Exponential backoff is applied between attempts.

<Tabs syncKey="syntax">
  <TabItem label="Declarative">
```typescript
import { createAgent } from "reactive-agents";

const agent = await createAgent({
  name: "prod-agent",
  provider: "anthropic",
  execution: { retryPolicy: { maxRetries: 3, backoffMs: 1000 } },
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
const agent = await ReactiveAgents.create()
  .withProvider("anthropic")
  .withRetryPolicy({ maxRetries: 3, backoffMs: 1000 })
  .build();
```
  </TabItem>
</Tabs>

## Cost Control

- Set a per-request and daily budget with `.withCostTracking({ perRequest, daily })` and handle `BudgetExceededError`. Setup and error handling: [Budget Enforcement](/features/cost-tracking/#budget-enforcement).
- Route simple queries to a cheaper tier with `.withModelRouting()` (builder-only). See [Cost-Aware Model Routing](/features/cost-tracking/#cost-aware-model-routing).
- Size the budget from expected volume: [Cost Optimization](/guides/cost-optimization/).

## Observability

### Metrics Dashboard

Enable the metrics dashboard to get a structured execution summary after every run: phase timing, tool call counts, token usage, estimated cost, and smart alerts.

<Tabs syncKey="syntax">
  <TabItem label="Declarative">
```typescript
import { createAgent } from "reactive-agents";

const agent = await createAgent({
  name: "prod-agent",
  provider: "anthropic",
  observability: { verbosity: "normal", live: true },
});
```
  </TabItem>
  <TabItem label="Builder">
```typescript
const agent = await ReactiveAgents.create()
  .withProvider("anthropic")
  .withObservability({ verbosity: "normal", live: true })
  .build();
```
  </TabItem>
</Tabs>

The dashboard is driven entirely by the EventBus. No manual instrumentation is required — `MetricsCollector` auto-subscribes to `ToolCallCompleted` and phase lifecycle events.

### Exporting Metrics

Call `agent.exportMetrics()` to retrieve metrics programmatically for forwarding to an external monitoring system (Prometheus, Datadog, etc.).

{/* docs-skip-typecheck */}
```typescript
const result = await agent.run("Process batch job");
const metrics = await agent.exportMetrics();

// Forward to your monitoring pipeline
await metricsClient.record({
  agentId: "prod-agent",
  duration: metrics.totalDurationMs,
  tokens: metrics.totalTokens,
  cost: metrics.estimatedCostUsd,
  steps: metrics.stepCount,
});
```

## Error Handling

### Global Error Handler

Register a handler to capture all agent errors in one place. The handler receives the error and a context object with task metadata for structured logging.

{/* docs-skip-typecheck */}
```typescript
const agent = await ReactiveAgents.create()
  .withProvider("anthropic")
  .withErrorHandler((error, ctx) => {
    logger.error(error.message, {
      taskId: ctx.taskId,
      agentId: ctx.agentId,
      iteration: ctx.iteration,
    });
    metrics.increment("agent.error", { type: error.constructor.name });
  })
  .build();
```

### RuntimeErrors Union

`RuntimeErrors` is the exhaustive union of all errors the agent can throw. Use it for type-safe catch blocks.

{/* docs-skip-typecheck */}
```typescript
import { RuntimeErrors } from "@reactive-agents/runtime";

try {
  const result = await agent.run(prompt);
} catch (e) {
  const error = e as RuntimeErrors;
  switch (error._tag) {
    case "BudgetExceededError":
      // degrade gracefully or queue for later
      break;
    case "GuardrailViolation":
      // return a safe fallback response
      break;
    case "MaxIterationsError":
      // return partial result if available
      break;
    default:
      throw e;
  }
}
```

### Unwrapping Effect Errors

When running Effect-based code directly, use `unwrapError()` to extract a clean message from an Effect `FiberFailure`, and `errorContext()` to retrieve actionable remediation hints.

```typescript
import { unwrapError, errorContext } from "@reactive-agents/runtime";

try {
  const result = await agent.run(prompt);
} catch (raw) {
  const error = unwrapError(raw);
  const ctx = errorContext(raw);
  console.error(error.message);
  if (ctx?.suggestion) {
    console.info("Suggestion:", ctx.suggestion);
  }
}
```

## Memory

Memory is configured once, in the [Memory guide](/guides/memory/). For production, decide:

- **Tier.** `{ tier: "enhanced" }` adds vector search and needs `EMBEDDING_PROVIDER` and `EMBEDDING_MODEL`. See [Retrieval Tiers](/guides/memory/#retrieval-tiers).
- **Growth.** `.withMemoryConsolidation()` (declarative `memory.memoryConsolidation`) decays and prunes episodic entries in the background. See [MemoryConsolidatorService](/guides/memory/#memoryconsolidatorservice--background-memory-intelligence).
- **Cross-run learning.** `.withExperienceLearning()` (declarative `memory.experienceLearning`) injects prior tool and error tips at bootstrap. See [ExperienceStore](/guides/memory/#experiencestore--cross-agent-learning).
- **Storage.** Set `dbPath` or rely on the default location. See [Storage Location](/guides/memory/#storage-location).

## Quick Reference

| Concern | Builder Method | Default | Production Recommendation |
|---|---|---|---|
| Prompt injection | `.withGuardrails()` | off | Enable |
| Cost limits | `.withCostTracking({ budget })` | off | Set per-request budget |
| Iteration limit | `.withMaxIterations(N)` | 10 | 20–50 for complex tasks |
| Min iterations | `.withMinIterations(N)` | none | 2–3 for research tasks |
| Output quality | `.withOutputValidator(fn)` | none | Validate structure for critical outputs |
| Answer verification | `.withVerificationStep()` | none | Enable for high-stakes decisions — on a REVISE verdict, reflect mode re-runs once with the verification feedback so the verdict shapes the final answer |
| Timeout | `.withTimeout(ms)` | none | 60\_000–300\_000 |
| Retry | `.withRetryPolicy()` | none | `{ maxAttempts: 3 }` |
| Observability | `.withObservability()` | off | Enable with `verbosity: "normal"` |
| Error handler | `.withErrorHandler()` | none | Set for logging/alerting |
| Kill switch | `.withKillSwitch()` | off | Enable for long-running agents |
